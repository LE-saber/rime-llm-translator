# 轻量离线机翻开发规划

状态：方案选定，尚未实现；本文件不代表当前 preview6 已替换引擎。
日期：2026-10-18。
基线：`feat/ubuntu-installable`，`9146860a33f762bae5495029df5a60092a6f09ac`。

## 1. 目标与选择

仅面向 Ubuntu 24.04 amd64、IBus-Rime、朙月拼音及用户的虚拟机。离线机翻负责提供基本可读的英文、日文草稿；精度和表达质量交给用户主动触发的云端 AI。开发、构建和自动测试使用 GitHub Actions；桌面虚拟机安装验收由用户完成，不使用 WSL。

选择 **Bergamot 原生 C++ 引擎 + Mozilla INT8 低内存模型**，优先使用 Mozilla 当前 `translations/inference` 中与模型相容的实现，固定源码提交及全部子模块版本。去掉离线运行时的 Argos、PyTorch、Stanza、spaCy、ONNX Runtime 和私有 Python venv。

默认模型组合：

| 用途 | 模型 | 权重文件解压后 | 完整模型资源压缩下载量 | 官方登记状态 |
| --- | --- | ---: | ---: | --- |
| 中译英 | zh-en base-memory，`cjk_retrain_base-memory_cNY_yaJCStGwnTeXgW8A5w` | 43,977,787 B | 38,287,826 B | Release Android |
| 英译日 | en-ja base-memory，`llmaat_finetune10M_qe8_f2_ApiGGQIwTKuF9i_k3n9Q2Q` | 43,849,787 B | 36,229,257 B | Release |
| 可选实验 | zh-en tiny，`cjk_icu_CQYVbMd3R5mtPx9PhXbNCA` | 25,461,051 B | 24,604,460 B | releaseStatus 为 null |

下载量包含模型、词表、词汇短名单，来自官方资源 HTTP 长度；以十进制 MB 计，默认两套约 **74.5 MB**，tiny 组合约 **60.8 MB**。这些数字不包含引擎、系统依赖及解压后的其他资源，不能直接当作安装后磁盘或运行内存。

选择 base-memory 作为默认候选，是因为它已有发布登记；其中中英模型的发布登记针对 Android，**仍必须通过 Ubuntu 原生引擎兼容性验证**。tiny 只在实际兼容性、草稿质量和性能通过后替换中英模型，不因文件更小而直接发布。

不选择词典逐词替换：体积虽小，但无法稳定处理基本语序和否定句。若 Bergamot 原生兼容性验证失败，唯一备选为直接使用 CTranslate2 INT8 加模型所需分词器，绕过 Argos 的重依赖；需要重新提交资源实测和模型兼容性结论。安装包只包含最终选定的一套后端，不同时捆绑两套，不回退安装完整 Argos 环境。

## 2. 翻译与调度方式

1. 中文原文保留，用于候选身份、显示和云端 AI。仅对离线机翻副本使用 Ubuntu 系统 OpenCC 的 `t2s.json` 归一化，简繁共用一个中英模型，避免再装繁中模型。台湾用语、专名和歧义字列入质量检查；不自动改用地域词汇转换。
2. 中文到英文运行一次；需要日文时复用英文草稿，再运行英译日。只启用英文时不加载英日模型。日文的中转损失属于已接受的草稿质量取舍，云端仍收到中文原文。
3. MT 管理进程使用系统 Python；计算放在独立的 C++ 子进程，通过有长度限制的 JSON 行协议通信。子进程默认单线程、单请求推理，优先使用单束解码，不生成多候选、对齐或质量评分。所有计算线程池都限制为 1，实测校验生效。
4. 保留现有 450 ms 防抖，提供 600–800 ms 低功耗配置。最多一个在算请求和一个最新待处理请求，旧待处理请求被覆盖；当前推理完成后立即检查请求代次，不为旧请求继续追加日译任务。不在每次按键时反复杀进程、重载模型。
5. 英文结果完成即写缓存并刷新候选，日文稍后补齐；无需等待两种语言都完成。保留现有无额外按键刷新和中文候选优先的行为。
6. 登录后不预加载权重，首次需要翻译才启动子进程；空闲 60 秒退出整个计算子进程，真正回收其权重和工作区。下次请求允许冷启动。超时或子进程崩溃时回收、退避重启，中文输入与 AI 服务继续工作。
7. MT 服务使用较低 CPU 调度优先级，默认 CPU 配额不超过一个逻辑核。单核仍可能满载；限制线程和配额是保护虚拟机交互，不是让推理没有 CPU 消耗。
8. 保留 1 字触发、1200 UTF-8 字节输入上限。长输入按句和分词器 token 预算分块、顺序处理，不静默截断；中转英文同样受预算限制。超时可保留已经完成的语言结果。
9. MT 缓存加入引擎版本、模型哈希、分词/归一化版本、源语言和目标语言，避免复用旧 Argos 结果。原始输入与简化副本始终可区分；候选刷新仍核对当前组合，不显示旧输入的迟到结果。
10. AI 继续独立运行，仅 `Ctrl+Shift+Enter` 请求兼容 API，发送中文原文和已有草稿。MT 失败、未安装目标语言或超时均不自动上传文本。其他目标语言先明确提示未提供模型。

## 3. 资源预算与估算边界

当前 preview6 已限制为 CPU-only Argos。上一轮 CI 安装日志中的运行时 wheel 下载总量约 341.6 MB，旧三套模型压缩资源约 269.4 MB；**尚无完整安装后的磁盘和真实模型推理 RSS 实测**。现方案磁盘 1.5–3 GiB、热运行内存 0.6–1.5 GiB 只是工程估算，不能作为基准测试结果。

新方案预算如下，除模型压缩资源大小外，均为开发目标，尚未测得：

| 项目 | 目标/门槛 | 统计口径 |
| --- | --- | --- |
| `.deb` 文件 | ≤ 120 MiB | 默认中英、英日模型与原生引擎全部包含 |
| 项目安装文件 | ≤ 250 MiB | 解压后模型、引擎、管理脚本、前端和许可证；不包含系统原有文件 |
| 新增系统运行依赖 | 单独列出，合计增量目标 ≤ 100 MiB | 在已具备目标 Rime 环境的 Ubuntu 24.04 上，按实际缺少的包计 |
| 空闲 MT | ≤ 40 MiB RSS | 管理进程；60 秒后计算子进程应不存在 |
| 英文热运行峰值 | ≤ 200 MiB RSS | MT 管理与所有计算子进程 RSS 合计 |
| 英文和日文热运行峰值 | ≤ 350 MiB RSS | 同时保留两套模型的 MT 进程树；AI 与原生 Rime 另报 |
| CPU | 默认最多一个逻辑核 | 记录线程数与实际 CPU 时间；`top` 中 100% 通常表示一个核 |
| 缓存 | MT ≤ 10 MiB，AI ≤ 10 MiB | 字节上限与各 350 项数量上限同时生效 |
| 安装临时空间 | 实测后声明峰值 | 包文件、解压、APT 缓存和升级保留空间分别记录 |

RSS 合计可能重复计算共享页，因此另报 PSS 和进程组内存峰值；不拿模型权重大小代替内存。系统新增依赖随用户已安装软件变化，报告必须附包清单。旧 Argos 环境尚未清理时，其磁盘应另计，不能宣称升级后已达到上述总量。

性能参考目标：在 GitHub Actions 记录具体 CPU 型号，并限制计算为一个逻辑核；10–30 字短句预热后，英文 p95 ≤ 1.5 秒、英日全部完成 p95 ≤ 3 秒，均不含防抖。冷启动单独报告；长句另测，不套用短句指标。CI CPU 和用户虚拟机不相同，不能将 CI 速度当作用户虚拟机的承诺。

保护中文输入是发布条件：推理不能进入 Rime/IBus 按键处理线程；负载下比较无翻译基线和启用翻译后的按键延迟、候选翻页、选词、提交、清空与切换输入源。超出预算先调整工作区和模型保活策略，再评估 tiny；不得通过无限排队或默认增大线程数掩盖问题。

## 4. 开发阶段和完成条件

### P0：原生可行性与资源验证，先过此关

- GitHub Actions 的 Ubuntu 24.04 原生作业编译最小推理程序，用真实中英、英日模型运行，不只测试导入或模拟结果。
- 核实最新模型所需的 CJK 预处理、源/目标独立词表、短名单及 INT8 格式；优先使用 Mozilla 同源 inference 实现，固定兼容提交，避免将最新模型直接配旧 Bergamot 示例程序。
- 固定全部资源 URL、压缩/解压大小、SHA256、许可证及来源。保存所用 registry 条目的快照；安装与启动不追踪浮动的最新模型。核实模型和各第三方代码可再分发，随包提供适用许可证和源码获取方式。
- 原生构建不能使用 Actions 机器的 `-march=native`。确定并声明 CPU 指令最低要求，验证运行时调度；不支持的 CPU 在加载模型前给出诊断，避免非法指令崩溃。
- 测量默认 base-memory 组合与 tiny 中英候选的磁盘、冷/热内存、CPU 时间、短句与长句耗时。禁网后重复推理，确保运行时没有隐式下载。
- 使用固定、可公开的简繁中文测试集，覆盖问候、日常短句、数字/单位、否定、专名、中英混合、标点和长句。自动检查空输出、截断、失控重复等；人工记录英日是否保留基本意思，不把“模型能运行”当成质量合格。tiny 需与 base-memory 逐项对照才可入选。
- 产出 `RESOURCE_REPORT.md` 和最终引擎/模型锁定清单。未满足兼容性、再分发和资源门槛，不进入完整替换；若试验备选 CTranslate2，则同样先提供实测结论。

### P1：接入轻量后端与资源回收

- 新增 `native/mt/` 下的原生计算程序与构建配置；改造 `src/rime_llm_translator.py` 的 MT 调用、部分结果写入、子进程生命周期与错误分类。
- 按第 2 节实现请求代次、最新待处理请求、独立英文结果、超时、空闲退出、长输入分块及缓存版本。
- 调整 MT systemd 服务的线程、优先级及配额；移除 Argos/PyTorch 专用环境变量。AI 服务保持独立。
- 为实际故障路径补必要测试：旧请求完成、英日部分成功、子进程退出/卡住、空闲后重启、损坏模型、繁体输入、超长输入和磁盘写入失败。
- 完成条件：真实模型接入现有 Rime/IBus 测试，迟到译文无额外按键即可出现，无意外提交或串到新组合的译文。

### P2：形成可直接安装的完整包及迁移路径

- `packaging/build-deb.sh` 输出一个包含默认两套模型、原生引擎和前端的 `.deb`；通过 APT 声明 Ubuntu 标准运行依赖，不在用户机器 pip 安装、编译或首次下载权重。
- 安装步骤缩为 APT 安装后执行 `setup`/`sync` 与 `enable`，必要时注销登录。API Key 可留空，离线翻译可独立使用。
- 保持原生 Rime 入口、用户词库、API Key 和现有配置。保留旧 `install-offline` 命令作为检查/迁移入口，不能继续安装重依赖；`doctor` 报告实际后端、模型版本、CPU 支持和残留占用。
- 提供显式迁移清理命令，只删除经过路径归属与符号链接检查的本项目旧 venv/模型目录；先确认新后端可用。共享 Argos 模型、全局 pip 缓存及非项目数据不自动删除。清理失败不破坏新安装。
- 磁盘不足、模型哈希错误或文件缺失时给出可读错误；安装和升级脚本不自动请求云端、不弹 Python 未处理异常。
- 更新中英文说明和手动验收清单，明确低内存模式、空闲回收、日文中转及旧环境额外占用。

### P3：GitHub 构建验收与交付

- 延续 Python/Lua、真实 librime 候选、原生 IBus 迟到缓存刷新测试；增加完整包安装后真实模型的断网翻译和资源统计，移除 Argos 安装检查。
- 测试全新安装、已有 preview5/6 配置的升级及清理、无 API Key、API 超时、重启服务、模型缺失/损坏和输入过程中计算子进程被终止。
- 运行连续输入/删除/切换候选压力场景，确认待处理请求有界；记录首次加载、重复短句、缓存命中、日文中转、长输入和空闲 60 秒后的内存。
- 资源报告附引擎/模型提交与哈希、runner CPU、资源限制、样本集、测量工具/口径和各次结果。不能通过一次平均值代替 p95，不能把模拟缓存测试当作真实机翻测试。
- 交付：完整 `.deb`、`SHA256SUMS`、`RESOURCE_REPORT.md`、升级清理说明和虚拟机手动验收清单。用户重点验证 GNOME/Wayland 候选绘制、实际延迟、CPU/内存占用和草稿可用性。
- 只有自动检查与用户目标虚拟机手动验收完成后，才将安装包标为已通过该目标环境验收。

## 5. 来源与待锁定信息

- [Bergamot 原生构建与库接口](https://github.com/browsermt/bergamot-translator)：C++ 原生库路线。
- [Mozilla Translations](https://github.com/mozilla/translations) 与 [inference 构建配置](https://github.com/mozilla/translations/blob/main/inference/CMakeLists.txt)：当前同源引擎、CPU 构建、关闭 CUDA 和可选 Python 绑定。
- [Mozilla 官方模型 registry](https://storage.googleapis.com/moz-fx-translations-data--303e-prod-translations-data/db/models.json)：2026-10-18 查询的模型条目、架构、发布状态与资源路径。上述容量不是对未来 registry 内容的承诺。
- [OpenCC](https://github.com/BYVoid/OpenCC)：离线简繁归一化；实现时针对 Ubuntu 24.04 自带版本编译，不引入最新 Python/Node 包。
- [CTranslate2 性能说明](https://opennmt.net/CTranslate2/performance.html)：仅作为备选后端的单线程、量化与单束解码参考。

待 P0 锁定：引擎及子模块完整提交、所有压缩资源的 SHA256、解压后总大小、模型配置、CPU 指令基线、实际新增系统依赖和真实推理资源报告。当前仅有元数据和下载长度证据，不声称原生组合已完成编译、推理或虚拟机测试。
